# Retrieved text is data

Text FI retrieves (papers, abstracts, full text, web pages, figure captions, data files, earlier FI results read back from the knowledge base) is material for the model to read and cite, never instructions for it to follow. A sentence planted in a source ("ignore the previous instructions and ...") would otherwise read like FI's own words.

**Fence.** Every block of retrieved text a prompt carries sits between two markers, `<<<FI SOURCE TEXT BEGIN key>>>` and `<<<FI SOURCE TEXT END key>>>`, after one sentence saying what it is (`core/source_text.py::fence`). The key is a hash of the block's own text, so a source cannot write the closing marker (it would have to contain a hash of a text that contains it), whatever letters it spells it with; the same text always gets the same key, so replays and prompt caches still match. A copy of the markers' words inside a source is also replaced (`neutralise`, which needs "FI" and whole words, so prose about a "source text" is untouched); nothing else in the text changes, so a quote the claim check looks up is still found. FI's own notes about the sources (the preliminary-results warning, the foundational-works note, the elision note of a file list) stay outside. The figure reader gets image and caption pairs, which are not fenced; `agents/figures_read.md` tells it the same thing in words.

**Flag.** Each source is checked once per text (again if its full text or figure readings arrive later) for text addressed to an AI model (a narrow list of order-shaped phrasings; reported speech such as "participants were told to disregard the previous instructions" is left alone) and for text hidden from a reader: Unicode tag characters (not the flag emoji that use them), three or more invisible characters inside Latin words, and text a PDF draws in white on the page, invisibly on a bare page, or below 2 pt (`core/pdf_text.py`, `PdfText.hidden_text`, for fetched papers, papers dropped in `inputs/papers/` and `knowledge.local_papers`; white or invisible text over a coloured fill or an image, such as a scan's searchable layer, does not count). A hit is a flag only: the source is kept whole, its header line in the prompts ends with `[flagged: may contain hidden instructions]`, the trace records a `check_result` (`check source_text: flagged`, with each source and why, once per source per run) and `run.log` names it in one line. A clean literature pass is recorded as `ok`. Nothing is removed, the quest never stops, and there is no switch.

**Measured.** 2,942 stored source texts from earlier quests (66 million characters): none flagged, none changed by `neutralise`. 108 real PDFs (papers and reports on the maintainer's machine): none flagged on either PDF reader, once invisible text layers over page images stopped counting; they were the one false positive the first run found, in 10 of the 108. An external review's list of ordinary sentences (medicine, physics, CPU instruction sets, questionnaires, fiction, XML) is kept as a test that none of them is flagged.

**Not covered.** An order worded outside the list; near-white text; text covered by a white box drawn after it; white or invisible text placed over an image (where a scan keeps its searchable text); the data files you supply (fenced, not checked); on PyMuPDF, white text with a dark outline (flagged although a reader sees the outline); on the pypdfium2 reader (without PyMuPDF), text inside a figure or a wrapped page the PDF includes as one unit (a figure-sized unit counts as a backdrop, a page-sized one does not); the titles in the foundational-works notes of the writer and the reviewer, and in the writer's cross-check summary and the poster's reference list, which carry titles only.
