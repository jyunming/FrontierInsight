# Documentation

Pick the path that matches what you want to do.

## I want to run a quest

1. **[Your first quest](first-quest.md)**: install, set a key, run the bundled example, find your paper. Start here.
2. **[Glossary](glossary.md)**: the words FI uses, one sentence each.
3. Your own topic: `fi --new` asks a few questions and writes the config ([first-quest.md](first-quest.md#7-your-own-question)).

## I want to change how it runs

- **[USAGE.md](USAGE.md)**: every setting in the YAML, with defaults.
- **[PROVIDERS.md](PROVIDERS.md)**: which model to use, what it costs, its terms.
- **[recipes.md](recipes.md)**: how-tos (local models, HPC, your own data, ...).
- **[INSTALL.md](INSTALL.md)**: install problems and optional tools (LaTeX, the knowledge layer).
- **[VSCode extension](../vscode-frontier-insight/README.md)**: the `@fi` chat.

## I want to know what FI checks, and what it did

- **[rigor.md](rigor.md)**: how FI checks its own experiments, and what each evidence level means.
- **[trace.md](trace.md)**: the ordered diary of a quest: `fi --trace <quest id>`.

## Reference (look things up; not for reading top to bottom)

- **[capabilities.md](capabilities.md)**: what FI can do, on one page.
- **[capabilities-reference.md](capabilities-reference.md)**: the long catalogue of every feature.
- **[features.md](features.md)**: the longer descriptions behind the README highlights.
- **[architecture.md](architecture.md)**: the stages and the extension points.
- `audits/`: historical reports.
