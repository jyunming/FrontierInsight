Frontier Insight

Automated research, end-to-end

From a one-sentence topic to a peer-reviewable paper. FI plans, runs the experiment, writes the paper, gets a critique, and ships the PDF.

What it does

You give it a research question. A LangGraph state machine of 13 nodes plans, retrieves prior work, designs the experiment, writes Python, runs it, analyzes the result, cross-checks against the literature, writes the paper, and reviews it — with checkpointing so a crash mid-quest doesn't lose work.

topic  →  clarify  →  literature  →  design  →  implement  →  execute  →  analyze
                                                                              ↓
                                                        cross-check ← write ← ↓
                                                                              ↓
                                                                review (loop)  ↓
                                                                              ↓
                                                paper.md + paper.pdf + slides ↓

Who it's for

  • Researchers who want a draft + comparable baseline before committing weeks of bench time.
  • Engineers investigating a question who'd rather have an end-to-end answer than open another 20 tabs.
  • Curious tinkerers running 200 toy quests on a long weekend just to see what's plausible.

How it differs from "just ask an LLM"

"Just ask an LLM"Frontier Insight
One LLM call. The model hallucinates.13 nodes, each with a focused prompt + grounded context.
No experiment — pure prose.Runs real Python in a sandboxed venv; figures come from real data.
No literature grounding.Retrieves from arXiv / OpenAlex / Crossref / Axon. Cites by content, not by guessed DOI.
No review.Single or multi-persona reviewer panel + adversarial critique.
No reproducibility.Bundles experiment.py + manifest. Quest dir is a complete deliverable.

Three ways to run it

Terminal

python launch.py --new                    # interactive interview
python launch.py --config my_quest.yaml   # from a config you wrote
python launch.py --proposal "..."         # plan before you run

VSCode Chat

@fi /new                            # interactive setup
@fi /update <quest_id>              # mid-quest tweak
@fi /proposal Compare RK4 vs Verlet on the Kepler problem

Web UI

python launch.py --serve            # http://127.0.0.1:8765/

The web UI exposes every CLI feature — a dashboard, an interactive setup form, dedicated pages for each tool (proposal, critique, digest, portfolio, summarize, analyze, fleet, ingest), live quest status with log streaming, file browser, cost & runtime chart, paper-iterations diff, tags, side-by-side compare, and a trash bin.

Choosing a provider

ProviderUnit billedBest for
GitHub Copilot
vscode_extension / copilot_cli		 Premium request (1 call = 1 unit) Bursty heavy quests. Flat-rate per-call dominates when prompts are large.
OpenAI / Codex
openai / codex / codex_cli		 Per-token Long-running automations. Skinny prompts win.
Claude
claude_cli		 Per-token Sonnet is the workhorse; reserve Opus for write + review.
Gemini
gemini_cli		 Per-token Cheapest cloud option for long-context tasks.
Ollama
ollama		 Free (local) Quality varies; use for high-volume cheap nodes or airgapped runs.

The web UI shows per-quest cost on the detail page (token-priced providers only — Copilot's premium-request unit is opaque to FI).

What you get when a quest finishes

Inside outputs/<quest_id>/:

  • paper/paper.md + paper/paper.pdf
  • figures/*.png — every plot the experiment produced
  • code/experiment.py — exact code that ran
  • slides.md / slides.pptx / poster.tex / talk.md (optional deliverables)
  • data/auto_collected/ — Axon hits + dataset-adapter output (no-simulation mode)
  • frontier_insight_summary.json — machine-readable index
