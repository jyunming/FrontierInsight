What it does

You give it a research question. It plans, runs the experiment, writes the paper, gets a critique, and lands the PDF — across a configurable pipeline you can run in your terminal, in VSCode chat, or in this browser.

topic  →  clarify  →  literature  →  design  →  implement  →  execute  →  analyze
                                                                              ↓
                                                        cross-check ← write ← ↓
                                                                              ↓
                                                                review (loop)  ↓
                                                                              ↓
                                                paper.md + paper.pdf + slides ↓

A LangGraph state machine of 13 nodes. Each node is an LLM call (or a real Python subprocess for execute). The state is checkpointed to SQLite so a crash mid-quest doesn't lose work — --resume picks up where it died.

Who it's for

  • Researchers who want a draft + comparable baseline before committing weeks of bench time.
  • Engineers investigating a question who'd rather have an end-to-end answer than open another 20 tabs.
  • Curious tinkerers running 200 toy quests on a long weekend just to see what's plausible.

How it differs from "just ask an LLM"

"Just ask an LLM"Frontier Insight
One LLM call. The model hallucinates.13 nodes, each with a focused prompt + grounded context.
No experiment — pure prose.Runs real Python in a sandboxed venv; figures come from real data.
No literature grounding.Retrieves from arXiv / OpenAlex / Crossref / Axon corpus. Cites by content, not by guessed DOI.
No review.Single or multi-persona reviewer panel + adversarial critique.
No reproducibility.Bundles experiment.py + manifest. Quest dir is a complete deliverable.

Three ways to run it

Terminal

python launch.py --new                    # interactive interview
python launch.py --config my_quest.yaml   # from a config you wrote
python launch.py --proposal "..."         # plan before you run

VSCode Chat

@fi /new                            # interactive setup
@fi /update <quest_id>              # mid-quest tweak
@fi /proposal Compare RK4 vs Verlet on the Kepler problem

This browser

  • + New Quest in the header — runs the same interview as the CLI.

  • Each quest gets a live status page; you can cancel mid-run.

What you get when a quest finishes

Inside outputs/<quest_id>/:

  • paper/paper.md + paper/paper.pdf
  • figures/*.png — every plot the experiment produced
  • code/experiment.py — exact code that ran
  • slides.md / slides.pptx / poster.tex / talk.md (optional deliverables)
  • data/auto_collected/ — Axon hits + dataset-adapter output (no-simulation mode)
  • frontier_insight_summary.json — machine-readable index
